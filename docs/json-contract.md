# JSON contract

For executable commands, `--json` writes exactly one UTF-8 JSON document to stdout on success. Meta commands (`--help` and `--version`) always remain plain text, even when `--json` is also present. `completion`/`completions` writes a deterministic plain-text shell script and rejects `--json`; it has no JSON envelope. Collections are `{ "items": [...], "pageInfo": { "hasNextPage": bool, "endCursor": string|null } }`. `view`, `create`, and `update` return `{ "issue": Issue }`; Issue includes `id`, `identifier`, `title`, `description`, `url`, `branchName`, `priority`, `team`, `state`, `assignee`, `createdAt`, and `updatedAt` (nullable remote fields remain `null`). Scalars are `{ "id": string }`, `{ "title": string }`, or `{ "url": string }`. Team configuration is `{ "team": Team }` when setting and `{ "team": string }` when displaying the resolved global setting.

Team, team-member, user, and project lists use the normal collection envelope. Project view and create return `{ "project": Project }`; project fields include `id`, `name`, `slugId`, `description`, `content`, `url`, `targetDate`, `teams`, `lead`, and `members` with nullable remote fields retained as `null`. Milestone lists use the normal collection envelope; view/create/update return `{ "milestone": Milestone }`, with `id`, `name`, `description`, `projectId`, and `targetDate`. Milestone deletion returns the established archived envelope and dry-runs use the established dry-run envelope. Team creation returns `{ "team": Team }`; `team id` returns `{ "id": string }`. User fields are `id`, `name`, `displayName`, `email`, `active`, and `avatarUrl`, with nullable remote values retained as `null`. Comment list uses the normal collection envelope; comment create/update returns `{ "comment": Comment }`. Issue archive and comment delete return `{ "result":"archived", "resource": { "id": string } }`; their dry-runs return `{ "result":"dry_run", "action": "archive|delete", "target": string }`. Document lists use `{ "items": [...], "pageInfo": {...} }`; create/update/view use `{ "document": Document }`. Document trash returns the established archived envelope and dry-runs use the established dry-run envelope with action `archive`. If bulk trash partially succeeds, JSON stdout is `{ "result":"partial_failure", "completedPhase":"remote", "completedItems":[{"id":...,"slugId":...}], "retry":... }` and exits 1. Confirmations and all ordinary failures produce no stdout.

`issue start --json` returns `result`, `issue`, `branch`, and `workflow`; branch action is `created`, `switched`, or `already_current`. If Git succeeded but Linear cannot be re-read or updated, JSON mode instead writes a `partial_failure` result with `completedPhase: "git"`, `workflow.action: "not_confirmed"`, and a retry command to stdout, then exits 1. In human mode, stderr reports the completed branch action, the unconfirmed workflow state, the retry command, and the underlying error. Normal JSON failures emit no stdout and one stderr document: `{ "error": { "code": "invalid_input|operational", "message": string } }`. Authentication and configuration failures use the same error envelope with their respective error codes.

A successful multi-document trash uses `{"result":"archived","resources":[{"id":"...","slugId":"..."}]}` so every trashed document remains visible. Raw document human output still escapes terminal control characters.
